### 1. Collection Group Query for Historical Notes

**File:** `Hone/Core/Repositories/SessionRepository.swift:246-277`

Added `getHistoricalNotes` method to `SessionRepositoryProtocol` and implementation:

```swift
func getHistoricalNotes(userId: String, activityId: String, limit: Int = 10) async throws -> [SessionActivity] {
    // Use collection group query to search across all sessions efficiently
    let snapshot = try await db.collectionGroup("activities")
        .whereField("activityId", isEqualTo: activityId)
        .order(by: "createdAt", descending: true)
        .limit(to: limit)
        .getDocuments()

    let activities = snapshot.documents.compactMap { doc -> SessionActivity? in
        do {
            let activity = try doc.data(as: SessionActivity.self)
            // Filter: only return activities with notes and not in-between time
            guard let notes = activity.notes,
                  !notes.isEmpty,
                  !activity.isInBetweenTime else {
                return nil
            }
            return activity
        } catch {
            print("Error decoding SessionActivity: \(error)")
            return nil
        }
    }

    return activities
}
```

**Key Design Decisions:**
- **Collection group query** instead of querying each session individually - more efficient
- **Filter out empty notes** and in-between time activities in compactMap
- **Sort by createdAt descending** to show most recent first
- **Default limit of 10** (UI shows 3 by default, expands to 10 max)
- **Graceful error handling** with compactMap skipping decode failures

func loadHistoricalNotes() async {
    guard currentActivityIndex < activities.count else { return }
    guard let activityId = activities[currentActivityIndex].activityId else { return }

    do {
        historicalNotes = try await repository.getHistoricalNotes(
            userId: userId,
            activityId: activityId,
            limit: 10
        )
    } catch {
        print("Error loading historical notes: \(error)")
        historicalNotes = []
    }
}

                                    .font(.caption)
                                    .foregroundColor(.secondary)
                                Text(notes)
                                    .font(.body)
                                    .foregroundColor(.secondary)

                            .padding(.vertical, 6)
                            .padding(.horizontal, 12)
                            .background(Color(uiColor: .tertiarySystemGroupedBackground))
                            .cornerRadius(8)
                        }
                    }

                    if historicalNotes.count > 3 {
                        Button(action: { showingAllHistorical.toggle() }) {
                            Text(showingAllHistorical ? "Show Less" : "Show All (\(historicalNotes.count) total)")
                        }
                    }
                }
                Divider()
            }

            // Current session notes with "This Session" label
            // ... rest of view ...
        }
    }

    private func formatDate(_ isoString: String) -> String {
        guard let date = isoString.toDate() else { return isoString }
        let formatter = RelativeDateTimeFormatter()
        formatter.unitsStyle = .abbreviated
        return formatter.localizedString(for: date, relativeTo: Date())
    }

## Technical Implementation Details

### Collection Group Query Approach

**Why collection group instead of querying each session?**

Traditional approach would be:
1. Query all sessions for user
2. For each session, query activities subcollection
3. Filter and aggregate results

This requires N+1 queries (one for sessions list, then one per session).

**Collection group query benefits:**
- Single query across all sessions
- Firestore handles cross-collection search
- More efficient as session count grows
- Simpler code (no nested loops)

**Path structure:**
```
users/{userId}/sessions/{sessionId}/activities/{activityId}
                        ^^^^^^^^^^^^^^^^^^^^^^
                        Collection group "activities" searches across all sessions
```

### Memory and Performance

**Query Performance:**
- Index-backed query with O(log n) lookup
- Limit to 10 results keeps payload small
- Results cached by Firestore SDK

**UI Performance:**
- Only 3 notes rendered by default
- Expand to 10 max (controlled by repository limit)
- No infinite scroll needed for practice notes use case

**Memory Management:**
- `@Published` array automatically manages SwiftUI updates
- Old historicalNotes array released when new activity loads
- No listeners needed (one-time query per activity)

### Date Formatting Strategy

**RelativeDateTimeFormatter advantages:**
- More human-readable ("1 day ago" vs "2024-03-02")
- Automatic localization
- Handles all time ranges (seconds ago → years ago)
- iOS system default formatting

**Fallback behavior:**
- If date parsing fails, shows raw ISO string
- Graceful degradation ensures notes always visible

## Edge Cases Handled

1. **No historical notes:** Section hidden entirely (clean empty state)
2. **Only 1-3 notes:** No "Show All" button displayed
3. **Date parsing failure:** Shows raw ISO string instead of crashing
4. **In-between time:** Filtered out (user doesn't need break notes)
5. **Empty note strings:** Filtered out by compactMap
6. **Decode errors:** Skipped via compactMap (resilience pattern)
7. **Network errors:** Graceful fallback to empty array with console log
