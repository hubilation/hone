**1. Update ContentView.swift:**
```swift
import SwiftUI

struct ContentView: View {
    @EnvironmentObject var authViewModel: AuthViewModel

    var body: some View {
        if let user = authViewModel.user {
            TabView {
                // Existing Activities tab
                ActivityListView(userId: user.id)
                    .tabItem {
                        Label("Activities", systemImage: "music.note.list")
                    }

                // NEW: Sessions tab
                SessionSetupView(userId: user.id)
                    .tabItem {
                        Label("Sessions", systemImage: "timer")
                    }

                // Existing Settings tab
                SettingsView(viewModel: authViewModel)
                    .tabItem {
                        Label("Settings", systemImage: "gearshape")
                    }
            }
        } else {
            LoginView(viewModel: authViewModel)
        }
    }
}
```

**Key decisions:**
- Sessions tab placed between Activities and Settings (central position for primary feature)
- "timer" SF Symbol for tab icon (clearly indicates session/practice functionality)
- Reuses existing user.id from authViewModel (consistent with Activities tab)
- Tab order: Activities (create), Sessions (use), Settings (configure)

**2. Test navigation flow:**
- User signs in -> sees TabView
- User taps Sessions tab -> SessionSetupView appears
- User selects activities -> taps Start Session -> ActiveSessionView appears
- User ends session -> SessionSummaryView appears
- User dismisses summary -> returns to SessionSetupView

**CRITICAL VERIFICATION STEPS - ALL MUST PASS:**

**1. Timer Readability from Distance (EXEC-02):**
   - Start any session from Sessions tab
   - Place iPhone on music stand or similar surface
   - Step back 10 feet (measure with tape measure or count 10 adult steps)
   - Verify you can clearly read hours, minutes, and seconds without squinting
   - PASS: All digits readable from 10 feet
   - FAIL: Digits blurry or unreadable -> font too small

**2. Background Survival (EXEC-13 - MOST CRITICAL):**
   - Start session, note the displayed time (e.g., 00:01:23)
   - Swipe up to home screen
   - Wait exactly 5 minutes (use secondary timer or watch)
   - Return to app (tap Hone icon)
   - Verify displayed time is approximately 5 minutes ahead of noted time (e.g., ~00:06:23)
   - Tolerance: ±5 seconds acceptable (account for return delay)
   - PASS: Timer continued accurately during background
   - FAIL: Timer frozen or significantly incorrect -> date calculation broken

**3. Force Quit Recovery (EXEC-15):**
   - Start session with 2+ activities
   - Complete first activity, add note "Test note before crash"
   - Skip to next activity
   - Force quit app (swipe up from bottom, swipe app preview up)
   - Reopen app
   - Tap Sessions tab
   - Verify active session detected with resume option OR session state preserved
   - PASS: Can resume session with notes and progress intact
   - FAIL: Session lost or data missing -> Firestore persistence broken

**4. Pause/Resume Accuracy (EXEC-03, EXEC-04):**
   - Start session, let run for 30 seconds
   - Tap Pause, note exact time (e.g., 00:00:30)
   - Wait 1 minute without touching device
   - Tap Resume
   - Verify timer continues from paused time (00:00:30 -> 00:00:31...)
   - Verify paused duration NOT added to elapsed time
   - PASS: Timer resumes exactly from pause point
   - FAIL: Timer includes paused time or resets -> pause logic broken

**5. Notes Functionality (EXEC-05, EXEC-06):**
   - During active session, type note "Great progress today"
   - Tap + button or press Return
   - Verify note appears below input field
   - Add second note "Need to practice more"
   - Verify both notes displayed (not replaced)
   - End session, check summary
   - Verify notes appear in activity breakdown
   - PASS: Notes save, display, and persist to summary
   - FAIL: Notes disappear or don't save -> storage broken

**6. Activity Queue Management (EXEC-07, EXEC-08, EXEC-09):**
   - Start session with 3 activities
   - Tap "Skip to Next Activity" button
   - Verify current activity changes to second activity
   - Verify timer resets (starts counting from 00:00:00)
   - In upcoming activities list, tap X on third activity
   - Verify third activity removed from queue
   - Tap Edit button, drag activity to reorder
   - Verify order changes
   - PASS: Skip, remove, and reorder all work
   - FAIL: Any operation fails or crashes -> queue management broken

**7. In-Between Time Tracking (EXEC-11):**
   - Start session with 2 activities
   - Complete first activity (or skip to next)
   - Verify "Start Next Activity" button appears
   - Wait 30 seconds
   - Tap "Start Next Activity"
   - Complete session
   - Check summary for "Break Time" section
   - Verify break duration approximately 30 seconds
   - PASS: Break time tracked and displayed in summary
   - FAIL: Break time missing from summary -> in-between tracking broken

**8. Control Simplicity (EXEC-14):**
   - Hold an object in your hands (book, water bottle) to simulate holding instrument
   - While holding object, attempt to:
     - Tap Pause button with thumb
     - Tap Resume button with thumb
     - Tap "Skip to Next Activity" button
   - Verify buttons large enough to tap accurately without fumbling
   - PASS: All controls operable with one hand while holding object
   - FAIL: Buttons too small or miss-tap frequently -> touch targets too small

**9. Session Setup Simplicity (SETUP-04 - 3 taps or fewer):**
   - From Sessions tab, count taps:
     - Tap 1: Select first activity
     - Tap 2: Select second activity
     - Tap 3: Tap "Start Practice Session"
   - Verify session starts (ActiveSessionView appears)
   - Total taps: 3
   - PASS: Session starts in 3 taps
   - FAIL: Requires more steps -> setup flow too complex

**10. Visual Progress (EXEC-10):**

   - Verify progress bar shows 0% (or 33% if first activity started)
   - Skip to second activity
   - Verify progress bar increases to approximately 33-66%
   - Skip to third activity
   - Verify progress bar shows 66-100%
   - PASS: Progress bar updates as session progresses
   - FAIL: Progress bar stuck or incorrect -> progress calculation broken
