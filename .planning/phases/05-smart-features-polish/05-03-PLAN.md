    Note every call site. The Statistics tab and Home tab both use this component.

    STEP 2 — Update WeeklySummaryCard.swift:

    Add `let streak: Int` parameter with default value `0`:
    ```swift
    struct WeeklySummaryCard: View {
        let sessions: [Session]
        let streak: Int         // add this; default 0 keeps Statistics tab call site unchanged
    ```

    Inside `if let summary = weekSummary { HStack(spacing: 24) { ... } }`, append a 4th stat column after the "Time Per Day" column, visible only when streak > 0:
    ```swift
    if streak > 0 {
        VStack(alignment: .leading, spacing: 4) {
            Text("Streak")
                .font(.caption)
                .foregroundColor(.secondary)
            HStack(spacing: 2) {
                Image(systemName: "flame.fill")
                    .foregroundColor(.orange)
                Text("\(streak)d")
            }
            .font(.title2)
            .fontWeight(.bold)
            .foregroundColor(.orange)
        }
    }
    ```

    Update the struct initializer: Swift synthesizes memberwise init, so adding `let streak: Int = 0` (with default) keeps all existing call sites that don't pass `streak:` compiling without changes.

    NOTE on WeeklySummaryCard's `else` branch ("You haven't practiced this week!"): Streak display lives only inside `if let summary = weekSummary`. If the user has a streak but no sessions THIS week, the streak won't display. This edge case is acceptable for v1 — the "no sessions this week" message is shown in that case and the streak display is a secondary stat. Document this known limitation in a code comment.

    STEP 3 — Update QuickStartView.swift:

    Replace the WeeklySummaryCard call:
    ```swift
    WeeklySummaryCard(
        sessions: sessionHistoryViewModel.sessions,
        streak: SuggestionsService.currentStreak(sessions: sessionHistoryViewModel.sessions)
    )
    .padding(.horizontal)
    ```
    This is a synchronous computed value evaluated each time QuickStartView re-renders (triggered by @ObservedObject sessionHistoryViewModel when sessions change). No new state needed.
